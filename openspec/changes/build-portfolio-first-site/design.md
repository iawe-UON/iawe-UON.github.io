## Context

当前项目使用 Hexo 8.1.1、NexT Muse、Markdown 文章和 Git 部署。根路径由 `hexo-generator-index` 生成文章列表，主题覆盖文件目前仅配置 Utterances；站点已有标签页、归档和约二十余篇文章，但没有作品集页面或统一的个人资料数据源。参见 `proposal.md` 的改造动机和四份能力规格的外部行为约束。

设计需要保持现有 Hexo 构建链、文章永久链接和 NexT 评论集成，不新增生产依赖。实现应集中在站点配置、自定义数据、增量 Nunjucks 布局、主题覆盖样式和少量原生 JavaScript 中，避免深度分叉 NexT 或引入独立前端应用。

## Goals / Non-Goals

**Goals:**

- 以可单独维护和测试的模板单元实现作品集首页、关于、简历、成果和博客列表。
- 通过一个结构清晰的数据文件维护个人资料、联系、简历和成果内容。
- 将作品集页面和博客页面纳入同一轻量主题系统、响应式规则和可访问交互约束。
- 在构建时继续使用 Hexo 数据与文章集合，在浏览器端仅处理主题切换、成果筛选和抽屉状态。
- 将对 NexT 上游文件的改动控制在新增布局和正式扩展点，降低后续升级冲突。

**Non-Goals:**

- 不建立 CMS、联系表单、后端接口、数据库或客户端文章搜索索引。
- 不预览或管理证书、附件和成果图片。
- 不重写文章详情、归档和标签生成器，不迁移已有文章 Front Matter。
- 不保证第三方 Utterances iframe 遵守站点自有界面的三色限制，但需要同步其明暗主题。

## Decisions

### 1. 使用 Hexo 路由生成器完成首页与博客迁移

将 `index_generator.path` 设置为 `blog`，并将 `index_generator.layout` 指向新增的博客列表布局。根路径通过 `source/index.md` 与作品集首页布局生成；关于、简历和成果同样使用带 `comments: false` 的独立页面源文件。

这样可让 `/blog/page/<n>/` 继续由现有分页生成器管理，同时不改变文章 `permalink`、标签和归档生成逻辑。备选方案是手写生成器或在首页混合文章列表，前者增加维护面，后者不符合作品集优先的信息架构，因此不采用。

### 2. 通过 NexT 正式扩展点做增量定制

新增 `portfolio-home`、`portfolio-about`、`portfolio-resume`、`portfolio-achievements` 和 `portfolio-blog` Nunjucks 布局，并用共享 macro 复用标题、卡片、标签和空状态结构。布局继承 NexT `_layout.njk`，从而继续复用头部、菜单、页脚和文章相关能力。

在站点的 NexT 覆盖配置中启用 `head`、`bodyEnd` 和 `style` 自定义文件路径；菜单、中文名称和评论配置也保留在覆盖文件中。备选方案是直接改写 NexT 核心布局或内嵌 SPA，都会扩大升级冲突或构建复杂度，因此不采用。

### 3. 使用单一 YAML 文件作为作品集内容接口

`source/_data/portfolio.yml` 是作品集内容的唯一来源，包含：

- `profile`: `name`、`role`、`tagline`、`summary`、可选 `avatar`、`skills[]`
- `contact`: `email`、`phone`
- `resume`: 可选 `pdf`、`experience[]`、`education[]`、`skillGroups[]`、`projects[]`
- `achievements[]`: `id`、`type`、`title`、`date`、`status`、`summary`、可选 `role`、`url`、`featured`

模板读取 `site.data.portfolio` 并在渲染前检查字段存在性。缺少可选字段时完全省略对应 DOM；头像缺失时根据姓名生成首字母标识。成果类型仅接受 `article`、`copyright`、`patent`，缺少必填字段的成果不会渲染。首页精选成果优先选择 `featured: true` 的前三项，最新文章直接从 Hexo 已发布文章集合按日期取得前三篇。

备选方案是将资料分散在各页面 Markdown 或通过浏览器请求 JSON；前者产生重复，后者引入运行时失败面，因此不采用。

### 4. 用站点自有 CSS 变量实现双主题和三色约束

在根元素设置 `data-theme="light|dark"`，每套主题仅定义 `--portfolio-bg`、`--portfolio-text`、`--portfolio-accent` 三个基础颜色。站点自有卡片、边框、焦点、按钮和标签均由这三项及其透明度派生；所有指定组件使用统一圆角尺度。第三方 Utterances iframe 作为外部界面不计入三色限制。

首次访问固定为浅色。头部注入脚本在正文绘制前用 `try/catch` 读取 `portfolio-theme`，仅接受 `light` 或 `dark`；无值或异常时选择 `light`。主题按钮在 `bodyEnd` 脚本中切换属性、更新可访问标签，并尝试写回本地存储。主题变化时通过 Utterances 的 `postMessage` 接口同步 `github-light` 或 `github-dark`。

不采用自动跟随系统偏好，因为已确认首次表现应始终为浅色；也不提供多套品牌色，以保持交互和视觉规则简单。

### 5. 使用服务端模板加原生 JavaScript管理成果状态

每张成果卡片渲染为带 `data-achievement-id` 的按钮，并为每项成果生成对应的隐藏 `<template>`。页面只保留一个原生 `<dialog>` 详情抽屉；打开时按标识克隆模板内容，避免把未转义 JSON 放入 HTML 属性。

筛选按钮使用 `data-filter` 控制卡片的 `hidden` 状态并更新 `aria-pressed`，没有可见卡片时显示空状态。`<dialog>` 在桌面断点固定为右侧面板，在移动断点固定为底部面板；关闭按钮、遮罩和原生 `Esc` 均调用统一关闭逻辑，关闭后焦点回到最近一次触发卡片。职责和 URL 不存在时模板不输出对应区域。

不使用第三方抽屉库或滑动手势，以减少依赖、状态分支和移动端误触。

### 6. 博客列表复用 Hexo 文章与标签集合

博客布局消费分页器提供的 `page.posts`，输出标题、日期、摘要、标签和详情链接；标签直接使用 Hexo 生成的标签 URL，分页仍由 `hexo-generator-index` 提供。文章详情继续使用 NexT 原有 `post.njk` 与 Utterances 配置，作品集页面和博客列表通过页面属性关闭评论。

该设计不创建第二套类别字段，也不在客户端加载完整文章索引。首页最新文章和 `/blog/` 列表共用文章集合，但分别由各自模板决定展示数量。

### 7. 响应式与可访问性作为共享样式约束

共享样式对网格子项设置可收缩宽度，并对标题、URL、联系方式和 CJK 连续文本启用安全换行；媒体、表格和代码块不超过正文容器。关键断点覆盖 360、768 和 1280 像素级视口。所有交互使用原生按钮或链接，保留可见焦点，并在 `prefers-reduced-motion: reduce` 下禁用抽屉和主题过渡。

测试层使用现有 Node/Hexo 能力完成构建输出和路由断言，浏览器级验证覆盖主题、筛选、抽屉、键盘操作及三种目标视口，不引入生产依赖。

## Risks / Trade-offs

- [根路径语义改变可能影响旧访客预期] → 在全站导航中明确提供“博客”入口，并保持所有文章详情和归档 URL 不变。
- [自定义 NexT 布局可能受主题升级影响] → 仅新增继承式布局与共享 macro，使用 `custom_file_path`，避免复制或修改主题核心文件。
- [示例联系方式可能被误认为真实信息] → 在数据文件中使用显式示例值和注释，发布前由维护者集中替换。
- [静态站点无法真正隐藏联系方式] → 按需求直接展示静态文本，不声称具备反爬或隐私保护能力。
- [第三方评论 iframe 无法执行三色限制] → 将约束明确限定为站点自有 UI，仅同步评论的明暗主题。
- [浏览器不支持或限制本地存储] → 使用异常保护并退化为当前页面可切换但不持久化。
- [原生 `<dialog>` 在旧浏览器表现不一致] → 以当前主流浏览器为支持范围，并在 CSS/脚本中保留非模态可见降级，不引入 polyfill。

## Migration Plan

1. 先加入数据、模板、样式、脚本和测试，不改变线上部署仓库。
2. 修改 Hexo 索引生成路径与 NexT 菜单，运行完整静态构建并检查所有目标路由。
3. 在本地服务中完成三种视口、浅深主题、成果抽屉、标签和评论回归验证。
4. 使用现有 `hexo deploy` 流程一次性发布生成结果；无需迁移文章数据或外部服务。
5. 若发布后需要回滚，恢复 `index_generator.path` 和原菜单配置，并移除新增页面/布局引用后重新生成部署；文章内容和永久链接无需恢复处理。
